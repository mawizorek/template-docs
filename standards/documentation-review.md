# Documentation review

What has to be true of a page before it is allowed to be `public`, and how
often somebody checks that it still is.

`authority` and `review_cycle` are not ceremony. A standard with neither is
folklore: nobody can say who decided it, and nobody is going to notice when it
stops being true. The `standard` type requires an authority and complains when
one is missing for exactly that reason.

## Before promoting a page to public

1. Every required field for its type is filled in.
2. Every link resolves. Check the build report, not your memory.
3. The opening paragraph says what the page is and who needs it, in one or two
   lines. It is also what a search result shows.
4. `revised` reflects when the content was last true, not when the file was
   last touched.

## What review is not

It is not a spelling pass. It is a check that the facts on the page are still
facts. A beautifully written page describing a room that was rebuilt two years
ago is worse than no page, because somebody will act on it.
